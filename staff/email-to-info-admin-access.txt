## 2. Case for Support â€” approve or deny access

Public page (visitors):  
https://www.americanfosterfutures.org/case-for-support.html  
*(or your Vercel site URL + `/case-for-support.html`)*

### What visitors do
1. Create an account or sign in.  
2. Submit an access request (organization optional + reason required).  
3. Wait until staff **Grant** access.  
4. Once approved, they click **Open Case for Support** to view the document.

### What staff do
1. Sign into **https://aff-futures-api.onrender.com/admin**  
2. Open the **Case for Support** tab (amber badge = pending count).  
3. Review name, email, organization, and reason.  
4. Click **Grant** or **Deny** (optional note).  
5. Filter: Pending / Approved / Denied.

**Notify yourself of new requests (optional):**  
On the API host, set environment variable:

- `ADMIN_NOTIFY_WEBHOOK` = a Slack/Discord/Zapier webhook URL  

New requests are also logged on the server and appended to  
`data/case-support-notify-log.jsonl` (when using the file backend).

## 3. Created user accounts

Accounts are created when people register via:

- The Case for Support access page, or  
- The mobile app (optional account / vault features)

### View account contacts (API)

Staff can list registered users (name, email, state â€” **no passwords**) with the admin key:

```http
GET https://aff-futures-api.onrender.com/api/admin/contacts
Header: x-admin-key: YOUR_ADMIN_API_KEY
```

Optional filter by state:

```http
GET https://aff-futures-api.onrender.com/api/admin/contacts?state=TX
Header: x-admin-key: YOUR_ADMIN_API_KEY
```

**Example (PowerShell):**

```powershell
$headers = @{ "x-admin-key" = "PASTE_ADMIN_API_KEY_HERE" }
Invoke-RestMethod -Uri "https://aff-futures-api.onrender.com/api/admin/contacts" -Headers $headers
```

**Note:** The web dashboard does not yet have a â€œContactsâ€ tab UI; use the API call above, or ask a developer to add a Contacts tab.

| Environment | Storage |
|-------------|---------|

| **Local / fallback** | JSON files under `aff-futures-api/data/` (e.g. `users.json`, `submissions.json`, `case-support-access.json`) â€” **not** for production secrets |
